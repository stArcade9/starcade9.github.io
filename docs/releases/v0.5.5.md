# Nova64 v0.5.5 — _Cracktro_

**Released:** 2026-10-04

> Re-cut of v0.5.4, whose cores and GitHub Release shipped but whose npm publish
> was blocked by a test suite that could not pass on a clean checkout. Same
> contents, plus the CI fix. v0.5.4 is not on npm; use v0.5.5.

A cracktro is the demoscene intro bolted onto software to make it run. That is
what this release does for Nova64 carts: the shape the README documented for
years could not actually execute in studio mode, and now it can.

One bug report started it. Chasing the cause turned up the same defect spread
across twenty documentation files, so this release fixes the example, fixes the
runtime, fixes every doc that taught the retired API, and adds the guards that
stop all three coming back.

## Highlights

### Studio accepts the module cart shape

`export function init()` was a syntax error under the studio executor — the path
`cart-runner.html`, `hero-embed` and every embedding host uses. Carts written
from the README failed before a single line of them ran, with
`Unexpected token 'export'` and no hint that module syntax was the problem.

This mattered beyond a documentation slip: `nova64@0.5.3` shipped that example,
so assistants trained on it emit the same shape confidently, and *every*
generated cart failed the same way.

`createStudioCartFunction` now strips top-level `export` and retries. Three
properties keep that safe:

- it runs **only after** `new Function` has already thrown, so a cart that parses
  today is never rewritten;
- it is string-, template-, comment- and regex-aware, so a cart that merely
  mentions the word — `print('export failed')`, a commented-out example, a
  regex like `/["']/` — is not corrupted;
- only `export` at the start of a top-level statement is touched.

`import` is deliberately still refused, with an error that explains why: an
export is a declaration modifier that can be dropped without changing behaviour,
whereas dropping an import would leave the cart referencing bindings that were
never created.

Covers `export function`, `export default`, `export const/let/class`, and
trailing `export { init, update, draw };` lists.

### The documentation stops teaching a retired API

The v0.5.0 namespace push retired the flat globals, but the docs never followed.
The README's first cart called `createCube(...)` and `print(...)` — and bare
`print` is `window.print`, so it opened the **browser print dialog** mid-frame on
a cart that otherwise looked like it was working.

- **566 call sites across 18 documents** now use `nova64.<group>.<name>`,
  resolved against `NAMESPACE_MAP` rather than edited by hand.
- Two documented functions did not exist at all: `circ(...)` is
  `nova64.draw.circle`, and `mouseButton(index)` is `nova64.input.mouseDown()`.
- Bug reports keep their reproduction code verbatim, and migration guides keep
  their `❌ Before` blocks, so the contrast still reads.

### Guards, so it cannot come back

- Tests walk `docs/` themselves — a doc added later is covered without anyone
  remembering — and fail on any retired bare global, or any documented
  `nova64.x.y` that does not resolve in `NAMESPACE_MAP`.
- `tests/playwright/studio-embedding.spec.js` drives the real browser embedding
  path: the module shape reaches `EXECUTE_SUCCESS`, `import` comes back as an
  actionable error, and opaque-origin code is still rejected.
- `scripts/sync-dist.mjs --check` now verifies the **108 runtime files** mirrored
  into `dist/`. That mirror is what the npm tarball ships, and a runtime fix that
  missed it never reached anyone who installed the package — which had already
  happened once during this very release.

### Release stamping

`pnpm release` wrote the version into `package.json` and nothing else, so every
version badge drifted. The docs site had read **v0.4.9 since that release** —
four versions stale. The bump now stamps the README badge and both copies of the
docs site, including the one inside `dist/` that ships to npm.

## Upgrading

No action required. Carts written against either shape run: the script form is
still what the docs recommend, and the module form now works instead of failing.

## Fixed

- `export` in a studio cart no longer throws `Unexpected token 'export'`
- README's first cart no longer opens the browser print dialog
- `circ` / `mouseButton` documented as functions that do not exist
- `dist/runtime/` could ship a stale copy of a fixed runtime file
- version badges frozen at v0.4.9 across four releases

## Also fixed in the v0.5.5 re-cut

`pnpm test` could not pass on a fresh clone -- the reason CI had been red since
2026-08-19 and the gated npm publish could never fire:

- `dist/assets/main-*.js` is a gitignored bundle, asserted before any build had
  run; the publish job also tested before building, and now builds first.
- `nova64-godot/godot_project/carts/wad-demo/code.js` is a gitignored local
  junction into `examples/`, read unconditionally since b9b9995a.
- `sync-dist.mjs --check` treated a missing `dist/` counterpart as drift; only 69
  of 96 carts have one tracked, so a clean clone reported 41 false drifts.

Each now tells "not built here" apart from "actually wrong", verified by cloning
the tag into a clean directory and running the suite the way CI does.
